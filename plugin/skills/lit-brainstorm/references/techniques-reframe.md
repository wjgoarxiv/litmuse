# Reframing techniques

Use these in Phase 0 and whenever the board shows the frame is wrong.

## How might we (HMW)

Turn a problem into an open invitation. Form: "How might we <verb> <who/what> so that <outcome>?"

Steps:
1. Start from the problem sentence. List the pains, constraints and surprising facts in it.
2. Rewrite each as an HMW. Make three altitudes: narrow (one symptom), medium (the user's stated goal), broad (the larger aim).
3. Remove solutions hiding in the verb. "How might we add a dashboard" is a solution; "How might we let people see progress" is a question.
4. Check it is neither trivial (answerable in one step) nor impossible (needs magic).

Example: problem "builds are slow". Narrow: how might we cut the slowest step? Medium: how might we shorten the wait for feedback? Broad: how might we make people not care about the wait?

## Five whys upward

Ask "so that what?" up to five times to find the real goal. "Faster builds" so that people get feedback sooner, so that mistakes are caught cheaply, so that releases are safer. Each level is a candidate frame. Stop where the user's ownership ends. Offer the levels to the user and let them pick.

## Assumption reversal

1. List 5 to 8 assumptions about how the thing works ("users log in first", "the team reviews every change").
2. Negate each one. Ask what a solution looks like in the negated world.
3. Keep the reversals that produce at least one concrete idea; label them `[reverse]`.

## Jobs to be done

Write job statements: "When <situation>, I want to <motivation>, so I can <outcome>." Cover the main job, one related job and one emotional or social job. Ideas can serve a job without resembling the current product.
