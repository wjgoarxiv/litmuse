# Changelog

## Unreleased

- The nine extension stubs and both READMEs now give three lines for installing an extension safely. The first only reads: it prints every folder Muse could load under that id (Muse's user skills, the personal `~/.claude/skills` and `~/.codex/skills` that Muse also loads, and the project's `.agents/skills` and `.claude/skills`). The second moves an existing copy in Muse's user skills, whole and with any file you added, into a dated folder under `$CONFIG_DIR/extension-backups/`, which Muse does not scan. The third is the `muse skills install` line. Muse 1.4.15 refuses to install over a folder that is already there, and `--force` and `muse skills update` rewrite the shipped files in place while keeping every other file, so the stubs no longer suggest `--force` for a newer edition: an update is the same three lines again.
- Removing an extension is now the move-aside line followed by `muse skills uninstall <id>`, which then only drops Muse's record. Run on its own, uninstall leaves the files you added in a folder Muse no longer lists, and that folder blocks the next install.
- Muse already records every install (source folder, time and file hashes) in `$CONFIG_DIR/skills/.muse/lock.json`, so LitMuse adds no receipt file of its own.
- The install notice now says that Muse refuses an occupied folder and names the verb that moves the old copy aside first. That line is printed by the installer, so no hook code changed: the hook digests are the ones 0.1.12 shipped, and Muse does not ask you to approve the LitMuse hooks again.
- New `npx @litfamily/litmuse extensions <verb>` runs the stubs' lines for you. `list` shows each of the nine as not installed, installed (with the source and time from Muse's lock), user-managed or competing with a same-name skill elsewhere (`--json` too). `check` lists what needs a look, each with the line that fixes it, and exits 1 when something does. `install <id...|--family f|--all>` stops and names a same-name skill in another folder Muse reads (`--allow-shadow` installs anyway and only warns), moves an occupied folder aside into a dated `$CONFIG_DIR/extension-backups/` folder, then calls `muse skills install`. `update` reinstalls only the installed extensions whose files differ from what Muse recorded. `remove` moves the folder aside and runs `muse skills uninstall`, and refuses a folder Muse did not install from a wjgoarxiv-skills edition. `prune-backups [--older-than <days>]` lists the backups with sizes and deletes them only with `--yes`.
- Every write verb is a dry run until you add `--yes`. `--from <clone>` uses your own wjgoarxiv-skills clone; without it LitMuse keeps a shallow, sparse clone of `variants/litmuse` in `~/.cache/litmuse/extensions-src`, and stops before any change when git or the network is missing.
- `doctor` runs the same check and prints one line (`INFO extensions` when clean, `WARN extensions` with the `extensions check` hint otherwise), and `install` adds a line pointing at `extensions check` when it finds something. Nothing changes on its own. The stubs and both READMEs name the verbs next to the manual lines.
- `extensions check` and `doctor` no longer flag a same-name skill of your own while that extension is not installed; `list` still shows it and `install` still stops on it. A file symlink inside an edition is compared by the content it points to, the way Muse records it, so `update` no longer reinstalls such an extension every time. When `muse skills list` fails, every verb stops with that error instead of reporting a clean slate. A dry run says whether it compared with the cached clone (`--yes` fetches first, so the result may differ) or will compare after the first fetch. When the same files come from a new folder, `update` reports `current` and only changes the source path in Muse's lock (written to a temporary file and renamed into place), with no move-aside and no copy.

## 0.1.12 — 2026-11-11

- LitMuse's core is complete and works on its own. The nine skills that make files are now LitFamily extensions, kept on the extension shelf wjgoarxiv-skills (https://github.com/wjgoarxiv/wjgoarxiv-skills); install the ones you use alongside LitMuse to get the full LitFamily experience. They are `lit-pptx` (decks), `lit-docx` (documents), `lit-diagram-drawer`, `lit-schematic` and `lit-scientific-visualization` (figures), `frontend-ui-ux` and `visual-qa` (design), and `lit-typographic-motion` and `readme-studio` (video-covers). To add one, clone the repository once (`git clone https://github.com/wjgoarxiv/wjgoarxiv-skills`) and install that skill's Muse edition: `muse skills install <path to your wjgoarxiv-skills clone>/variants/litmuse/<skill> --scope user`. The Muse edition carries its own helpers, fonts and lockfiles and sets up any engine it needs on first use, so it needs no LitMuse hook, approval or runtime command.
- `install` and `update` now say this in a short block before the closing status line, and the first Muse session after a new version says it once more: Muse does not show a hook's own message, so the SessionStart context asks the model to pass it on in its first reply, and a resume of that session keeps the same text. On an upgrade the block also names `~/.local/share/litmuse/runtime/` when an earlier LitMuse left engines there. A dry run, a preview without `--yes` and every `--json` output carry none of it.
- An upgrade over a bundle with edits inside one of those skills still stops with `FAIL destination modified`, and now also says that the skill became a LitFamily extension, gives its install line and names the user-skill folder (`~/.config/muse/skills/<skill>/`) to carry the edits into.
- `doctor` shows an `INFO leftover` row while `~/.local/share/litmuse/runtime/` is still there.
- Each moved skill keeps a same-name stub that calls it a LitFamily extension: its `lit` routes, catalog entry and doctor row stay. The stub hands over to the copy you installed, or gives the install line and builds nothing in its place. `doctor` reports an installed copy as `INFO moved`, not as an overlap, and LitMuse install, update and uninstall leave these user copies alone.
- Removed with those skills: the office runtime, the `diagram`, `readme`, `sciviz` and `motion` engines, the `litmuse runtime` command (and `npx @litfamily/litmuse runtime install all`), and the motion done-check in the Stop hook. `doctor` no longer lists LibreOffice, pandoc, Poppler, xelatex, ffmpeg or libwebp. The old engine caches under `~/.local/share/litmuse/runtime/` (or `$XDG_DATA_HOME/litmuse/runtime/`) are no longer used and can be deleted.
- `lit-scientific-visualization` now installs under its own id instead of `scientific-visualization`. A copy installed under the old id is no longer picked up: install the Muse edition and remove the old copy with `muse skills uninstall scientific-visualization`.
- The hook code changed, so Muse asks you to approve the LitMuse hooks again after the update, and `muse plugins update` asks again for the agents; `npx @litfamily/litmuse install` lists them and asks once.
- `skills.lock.json` replaced the pinned skill-depth and pack-list fixtures.

## 0.1.11 — 2026-11-11

- `lit adhd` now opens with a KPI board instead of the per-session brief. The board shows, in your language: the one thing to do now and the exact text to type (`go`, `lit continue`, `lit approve`, a `lit start` command, or what to wait for), a done / in progress / waiting on you / left count with an overall bar, up to four milestone rows with ten-cell bars, the last five things finished, the next seven still to do, and up to five reminders such as a session waiting on you, uncommitted changes or unpushed commits, lanes still working, or a plan untouched for a week. The collector computes and prints the board itself (`litmuse rewind --lang ko|en`), so the numbers never come from the model. The old per-session brief stays one word away: `lit adhd 자세히` / `lit adhd detail` (`--detail`).
- The prompt hook text changed, so Muse asks you to approve the LitMuse prompt hook again after the update.

## 0.1.7 — 2026-11-03

- Muse keeps the cached conversation across turns more often. The once-a-day suggestion to run `lit adhd` used to sit in the session-start text, which Muse rebuilds on every resume and places before the whole conversation; the line appeared on one resume and vanished on the next, so the cached history behind it was thrown away twice. The suggestion now rides on the first plain prompt instead, once per day as before and never while a route is live, and the session-start text stays the same for the whole session.
- Each hook now checks the code digest of only the files it runs. Before, every hook call also read the motion engine and the humanizer detector; now only Stop and PostToolUse do. A hook call is about a millisecond faster; most of its time is Muse starting Node, which LitMuse cannot change.
- The hook code changed, so Muse asks you to approve the LitMuse hooks again after the update.

## 0.1.6 — 2026-11-01

- `lit-typographic-motion` can lay real keyed footage over a stage film. A stage declares chroma-keyed clips in `stage/clips/clips.json` (an id, a folder, a frame count and a rate), the frames are 8-bit RGBA PNGs with real transparency, and the page registers each clip once with `LitStage.clip` and calls the returned function from `render(t)`; the frame shown is a plain function of film time, so a cue is `start = cue - (N - 1) / fps` and the flash audit and determinism replay see the final pixels. A declared clip is held to its own caps (12 clips, 360 frames in one and 1500 in all, 40 MB in one and 128 MB in all, 720 px on the long side, 30 fps) and no longer trips the flipbook rule; an undeclared frame folder is still refused with exit 17. Cover mode takes no clips. The manifest and the report list each clip.

## 0.1.5 — 2026-10-31

- `lit-adhd` counts the other sessions and herdr agents at work before it offers this session's own next step. Before, the session that had started them was still told to type `lit continue` (a paused workflow) or `go` (its own start-work run) while they worked, and its own card showed `lit continue`. Now it says to wait for them and keeps `go` silent; a pending approval is still offered, and `lit continue` typed by hand still works.
- LitMuse can now leave a short block of ground rules in Muse's own user rules file, `~/.config/muse/AGENTS.md`, which Muse loads at the start of every session. The hooks keep carrying the full guidance; the block only says that `lit` is LitMuse's activation word, where plans and handoffs live, that nothing is pushed, published, tagged or version-bumped without a yes, and that work counts as done after its tests pass and the changed surface was checked. It is yours to decide: an interactive install asks once (a No is remembered), `--yes` adds it, an install with no terminal and no `--yes` never writes it, `--no-agent-file` skips one run, and `litmuse config agentFile off|on` removes or restores it at once. Only the marked lines are LitMuse's; your text stays byte for byte, removing the block (or `uninstall`) returns the file as it was, and a copy of your file is saved the first time. A symbolic link, a non-UTF-8 file, a damaged marker pair or a file past Muse's 32,000-byte load limit is left alone and reported. `doctor` and `status` show the state.
- `lit-adhd` no longer tells you to type `go` while other sessions or herdr agents are still working in this repo: it says to wait for them, or to answer the one waiting on you, and ends with "Do not type `go` until they finish." It offers `go` only for a step `go` actually runs and only for this session's own work, so an approval step or another session's run never carries it. Its handoff suggestion skips items already marked done and reads the newest handoff file. A `go` typed after the brief first checks that the step still holds, and starts nothing if it does not.
- The hook code changed, so Muse asks you to approve the LitMuse hooks again after the update.
- A new `ci.yml` workflow checks every push and pull request to `main`: the tests, the version, hook-digest and legacy-token checks, and the packed file list, on Node 22 and 24 with no `muse` on the runner. One `lit-adhd` test no longer fails when it runs inside a herdr pane.

## 0.1.0 — 2026-10-22

First release of LitMuse, the LitFamily member for Meta's Muse Code (built and probed against Muse Code 1.4.10).

- Muse plugin `litmuse`: 39 skills, 4 commands (`/lit`, `/lit-korean`, `/lit-status`, `/lit-hud`), 10 hooks and 11 agents.
- Bare `lit` activation through the UserPromptSubmit hook; SessionStart context steers lit routes to LitMuse skills when Muse also loads personal rules and skills from other tools.
- lit-plan gate: PreToolUse keeps write_file, edit_file, apply_patch (including patch targets and moves) and delete_file inside `plans/` and `.litmuse/` after resolving `..` and symlinks, allows only provably read-only shell commands, lets only read-only LitMuse agents be spawned (workflows, schedules and image generation wait), and Stop holds the turn once until `plans/<slug>.md` exists. A negation-cluster guard counts only the negations a write adds to Markdown and stays off on the lit-humanizer route. A session ledger of tool events lives under `.litmuse/ledger/`.
- `/lit <route>` and `/litmuse:lit` activate routes like a bare `lit` prompt.
- `lit` re-entry: the first `lit` of a session sends the full activation; a later `lit` while the same route is active sends a note under 600 bytes without the skill re-read line and keeps the route state (so the lit-plan gate does not restart); `lit <other route>` switches with a full activation; a bare `lit` or `lit continue` resumes a plan already started with start-work; `lit new` and `lit restart` start over; a bare `lit` with nothing active or resumable asks what to run. Unreadable state falls back to the full activation.
- During lit-plan every tool goes through an allowlist (read-only tools; plans/ writes; one plain read-only shell command with per-program flag lists; read-only `litmuse/*` children); MCP and unknown tools are refused. Route state lives outside the workspace under `$XDG_STATE_HOME/litmuse/`, with a journal so a missing or damaged state file keeps a planning limit on.
- Each hook's declared command carries a digest of its code (`--digest`); a hook whose code differs refuses to run, and an update that changes a hook makes Muse ask for approval again.
- `npx @litfamily/litmuse install` stages an owned bundle, backs up the Muse files it changes, installs at user scope, lists the 21 hook and agent approvals and asks once; `--dry-run`, `--yes` and `--approve` cover previews and scripts. Symlinked, foreign or edited destinations (bundle, backups, receipt, update cache) stop the install before its first write, with the exact command to move them aside; `uninstall --discard-modified` clears an edited bundle. An install that finds LitMuse registered from another path explains it instead of updating that copy.
- `doctor` reports every approval, skill enrollment, catalog bytes against the 32 KB cap, overlaps with personal skills, and missing runtimes for the document and tooling skills. `models` lists the host catalog. `uninstall` removes the plugin and the bundle.
- Every skill ships at full family depth with its own references, scripts, templates and data inside its folder: the slide and document engines (shared `plugin/lib/` office runtime), the diagram engine with 61 types, the interface design corpus with its contract validator and browser probe, the humanizer rules and scanners, per-language code references, and research, conference and wiki modes. New skills: `lit-brainstorm` (divergent ideation that scores a shortlist and hands off to deep-interview or lit-plan), `lit-team`, `autoconference`, `rules`, `lit-burnoff-file`, `lsp` and `lsp-setup` (checker CLIs, since Muse has no LSP tool). `review-work` runs plan review or work review, picked from what exists and forceable; `litgoal` sets and keeps the finish line on Muse's native goal while lit-loop and start-work run toward it.
- Pinned engines (`office`, `diagram`, `readme`, `sciviz`) install on first use into `$XDG_DATA_HOME/litmuse/runtime/<name>` only; `npx @litfamily/litmuse runtime status|install <name|all>` checks or pre-warms them, and `doctor` lists each with its pre-warm command. The Python environments (office, sciviz and the motion audio tier) build from the newest `python3.X` between 3.10 and 3.14 on PATH, so a newer `python3` that the pinned wheels do not cover yet is passed over; `LITMUSE_OFFICE_PYTHON`, `LITMUSE_SCIVIZ_PYTHON` and `LITMUSE_MOTION_PYTHON` name one interpreter instead.
- Continuation and resilience hooks: Stop keeps start-work going while plan rows (including F1–F4) are open and litgoal while criteria are open, at most 3 holds in a row without progress, released by a pause word or a BLOCKED/PAUSED/CANCELLED ledger note and never on an unapproved plan; PreCompact writes a redacted `.litmuse/handoff/latest.md` and SessionStart re-injects it once after compaction (Muse gives hooks no context percentage, so there is no percent trigger). PreToolUse refuses a write that adds a hedge cluster to Markdown or text prose; PostToolUse passes added whole-line comments to comment-checker and runs an advisory lit-humanizer check on written prose. The hooks keep a live stage record (route, plan rows, running child agents, goal) shown by `/lit-status` and `litmuse status --card`; `litmuse style eli5|asd-ste100|off` adds an answer style through SessionStart, since Muse rejects plugin output styles.
- `lit-typographic-motion`: a film director that writes a treatment, then renders through the bundled deterministic stage renderer (HTML/SVG/Canvas/WebGL pages, 16:9 or 9:16) or the WebGL2 type engine (kinetic type, lyric and quote videos, title sequences), with a generated sound bed, look rounds on the rendered frames and a QA gate (flash audit, legibility, determinism, sound). Cover mode makes a silent, seamless README loop: one `renderFrame(t)` page with a loop kit that refuses clocks and entropy during capture, 2x capture, animated WebP, and a gate on the decoded file (G0–G6, flash, seek order, base-art SSIM) whose `--strict` TARGET includes 2 MiB; three recipes with pinned gate rows, four slide-like negatives that must keep failing, a timestamped defect log with window re-renders, and an asset list that stops on a missing file. `lit motion|film|video|영상` and film-making tasks route to it; PostToolUse records renders and the images `read_file` opened, and Stop holds the turn until the skill's done-check passes. Its `motion` engine installs only from a terminal (`npx @litfamily/litmuse runtime install motion`); `doctor` adds ffmpeg and libwebp rows.
- `/hud` preset documented in `docs/hud-preset.md`.
- README cover: the seven-member LitFamily motion film with LitMuse in the sixth bay, plus a still for reduced motion.
